# Tests

Plain Node scripts — no framework, no install for the first two.

| File | Run with | Checks |
|---|---|---|
| `payload-parity.test.js` | `node tests/payload-parity.test.js` | **The safety net.** An unedited payload template assembles byte-identically to the classic `buildPayload`. If this fails, turning templates on would silently change what every character receives. |
| `payload-templates.test.js` | `node tests/payload-templates.test.js` | Auto-drop of empty sections, role markers, value substitution, unknown-name reporting, the disabled path. |
| `engine-parity.test.js` | `npm i playwright` then `node tests/engine-parity.test.js` | **The engine safety net.** For every engine in `ENGINE_PARTS`, the unedited default template assembles the same user message the hand-written concatenation used to. Runs three value shapes per engine (all present, all empty, alternating). |
| `bare-pieces.browser.js` | `node tests/bare-pieces.browser.js` | **The go-live check.** On a real scene with a real character: templates are active on a fresh install, the default template is byte-identical to the classic payload, and "Erase built-in headings" removes the app's wording while keeping every piece of story data. |
| `tts-inworld.browser.js` | `node tests/tts-inworld.browser.js` | All chat speech runs on Inworld: no xAI function, roster, engine setting or UI survives; `voiceIdFor` falls back to the call voice; the WAV encoder produces valid RIFF including for a minute-long clip; delivery tags are always stripped; the `spoken_delivery` block keeps its id but loses the coaching; settings still save with the removed inputs. |
| `img-all-chars.browser.js` | `node tests/img-all-chars.browser.js` | Every character is illustrated, always: the "Characters that get images during dialogue" picker, its buttons, its four helpers, `imgCharAllowed`, `state.imgChars` and its storage key are all gone; a character beat and a narration beat both reach `illustrate`; a leftover `sm_imgchars` selection from an older build suppresses nobody; the gallery's unrelated `_imgChars` folder helper is untouched and settings still save. |
| `tts-steering.browser.js` | `node tests/tts-steering.browser.js` | Inworld TTS-2 steering: the normal and heat delivery blocks exist as separate fragments and editing one leaves the other untouched; the right one reaches the right turn (normal / heat / typed text / voicing off), the reset still fires on a stale transcript, and a written direction survives `ttsCleanText` and `extractDialogue` while `_dispText` hides it from the bubble — including one longer than the old 32-char cap. Brackets that are not directions ([Scene: x], [OOC: x], [3s], [/whisper]) are dropped. |
| `placeholders.browser.js` | `node tests/placeholders.browser.js` | `{{char}}`, `{{self}}`, `{{user}}` and `{{target}}` resolve in the Global Base Instruction and the Response Format Rules (both were concatenated raw before, so no placeholder ever worked in either); an unsupported token is still passed through rather than blanked; the editor warns live about any `{{token}}` the box will not fill — including a dotted one like `{{npc.name}}`, which `fillTpl`'s `\w+` pattern cannot even see — names what IS supported, renders under the real textarea and clears when corrected. |
| `update-check.browser.js` | `node tests/update-check.browser.js` | The new-build check: the bar starts hidden, shows and dismisses, and stays dismissed for the page; the build stamp calls the checker and `swCheck`/`updCheckNow` are reachable from global scope rather than trapped in the boot block; unforced checks are throttled to one per five minutes while forced ones always go through, and a throwing `update()` is swallowed; an update on an already-controlled page raises the bar while a first install stays silent; the bar clears the nav and fits a 412px phone. |
| `every-fragment-editable.browser.js` | `node tests/every-fragment-editable.browser.js` | **The no-hidden-prompt net.** Every fragment any block declares has a real textarea in the editor, and every shipped default is reachable from some block. Six were unreachable before — `task` ("# TASK You are {{char}}…"), `gm_private_lock`, `format_header`, `narr_shape`, `heat_format`, `text_format` — because the renderer drew fragments only for dynamic blocks and returned early for prompt-backed ones. Also checks the TASK line edits through to the built payload and resets back. |
| `scene-dock-reach.browser.js` | `node tests/scene-dock-reach.browser.js` | The scene player is reachable with **no image on screen** — the case that previously had no route at all — in portrait and landscape: the playback menu carries a Scene row, it opens the picker, the dock opens at real size inside the viewport, the row then reads as playing and closes it, and the other playback rows still toggle. |
| `drives-brakes.browser.js` | `node tests/drives-brakes.browser.js` | The id/superego pass: the momentary block only claims a tension when the second axis genuinely opposes the first (desire+comfort is not a conflict; desire+fear is); every relationship is injected in full again, with an absent spouse keeping their prose and an absent/present marker; the `drives` block sits after the feeling, drops a side that is empty, never carries a digit, and stays out of the payload until the engine has written; the engine prompt is registered, refuses to decide the outcome, and its signature moves with the situation but not otherwise. |
| `narration-privacy.browser.js` | `node tests/narration-privacy.browser.js` | What crosses between characters. On the default only quoted dialogue does — another character's `*narration*` and `_thoughts_` are both private — while the player's actions and a character's own lines stay whole. The `seen` and `off` modes still behave, an old stored `true`/`false` maps to the new default/`off`, the line-you-answer agrees with the transcript about what was witnessed, and the three-way setting round-trips. |
| `thought-style.browser.js` | `node tests/thought-style.browser.js` | Internal thoughts read as their own channel in both themes: `md()` tags `_thought_` with its own class and leaves `*narration*` alone, an ordinary `snake_case` underscore is untouched, and in the bubble the thought is measurably dimmer than the speech around it while still clearing a 3:1 contrast ratio, italic, with a rule down its left, and at a different weight from narration. |
| `memory-period.browser.js` | `node tests/memory-period.browser.js` | Memories carry the part of the day, not just the day. A memory stamped with the current day AND period is never retrieved — that is the scene the character is standing in — while earlier today, yesterday, and any memory with no period recorded still reach them, and the exclusion moves with the clock. The reconciler fires on a period change and refuses a day roll, leaves a single fragment alone, folds several into one, keeps the highest importance, caps at three, and loses nothing when the call fails or returns junk. |
| `cue-editor.browser.js` | `node tests/cue-editor.browser.js` | Writing clip descriptions against the clip. Records a real seekable webm in the page rather than stubbing, then checks the cue sheet shows the video with native controls, reads its duration, tracks the playhead, nudges ±1s without going below zero, stamps a row from the playhead (`set`), jumps the clip to a row (`go`), adds an already-stamped row, round-trips through save, and stops the clip on close. Also pins that no scrub bar leaked into the scene dock or the in-chat clip. |
| `language-rule.browser.js` | `node tests/language-rule.browser.js` | The story-language rule is callable on its own: bare `format` carries the app's rules without it, `format//full` still carries both, `language_rule` is the rule alone, your own rules plus the language rule pull in nothing else, and the default template stays byte-identical. |
| `debug-view.browser.js` | `node tests/debug-view.browser.js` | The Debug screen's payload view: "As sent" is the default and is the verbatim request body — valid JSON, one system bracket, each dialogue turn its own bracket, one user bracket, no capsule decomposition. The switch flips to capsules and back, and the choice is remembered. |
| `values.browser.js` | `node tests/values.browser.js` | The `{{value}}` placeholders: every one resolves in a reply payload, the character-scoped ones are withheld from engine templates and flagged there rather than sending a blank, and both editors list what is available. |
| `parts-ui.browser.js` | `node tests/parts-ui.browser.js` | The ordered parts list on a 412px phone: every part leads with its name, copy/used by/arrows sit below without clipping, reordering still works, and the engine payloads card shows its prompt keys. |
| `engine-ui.browser.js` | `node tests/engine-ui.browser.js` | The engine template UI on a 412px phone: the filter narrows 65 engines and reports an empty result, each engine's piece list renders lazily with plain names, and `edit` opens the prompt box for `prompt` while explaining itself for pieces the app builds. |
| `payload-ui.browser.js` | `node tests/payload-ui.browser.js` | The payload settings UI on a 412px phone: the switch keeps its 46×26 box with the label outside it, piece rows show plain names with no clipping or horizontal overflow, and every Edit button opens and highlights the right editor. |
| `video-cues.browser.js` | `node tests/video-cues.browser.js` | The video time-mark chain: marks stored and ordered, the gate's reasons, the mark reaching the character's payload with templates on, the auto-response wiring, and that an ordinary turn neither inherits the cue nor logs phantom warnings. |
| `payload-templates.browser.js` | `npm i playwright` then `node tests/payload-templates.browser.js` | Loads `index.html` in Chromium: boot without errors, the editor renders, validation warns on unknown names, the toggle persists, parity holds in the real app. |

The first two extract the relevant functions out of `index.html` at run time, so they cannot
drift from the shipped code.
